# Development

## Setup
Requires `uv`, Node 22, and (optional) Docker.

    make setup          # uv sync + npm ci + pre-commit hooks
    uvx pre-commit install --hook-type pre-commit --hook-type pre-push   # hooks only

## Run
    make dev-api        # FastAPI on :8000
    make dev-web        # Vite on :5173, proxies /api -> :8000

The frontend defaults to `VITE_API_MODE=mock` (in-browser backend, fully static). Use `VITE_API_MODE=live` to talk to the API.

## Run against the chain adapter (`CHAIN_MODE=l1`)
Default is `CHAIN_MODE=sim` (in-memory chain, no setup). To run the API on a Guardian L1:

    make contracts-deps && (cd contracts && forge build)   # Foundry: ~/.foundry/bin
    make l1-local-bootstrap                                # fresh local Guardian L1 + deploy + seed policy v1 + hand over + verify (~2.5 min)
    cd Backend && uv run --env-file .env.l1-local uvicorn guardian.main:app --port 8100
    cd Backend && uv run python ../infra/l1/e2e_scene4.py  # scene 4 through the API on the real node (optional)
    make l1-local-down                                     # always stop the network when done

`make l1-local-bootstrap` is `l1-local-up`, then `deploy-contracts` (the Deploy, Seed and Handover scripts in `contracts/script/`), `VerifySeed` and `verify-handover` (`VerifyHandover` fails if the deployer still has any role or power). It also writes `Backend/.env.l1-local` (CHAIN_MODE, DEMO_MODE, DEPLOYMENTS_FILE, GUARDIAN_SEED_FILE and one `L1_KEY_<SEED_ID>` per demo actor, generated by `infra/l1/local_env.py` from the PUBLIC `test ... junk` mnemonic; ignored by the VCS) and `Backend/deployments/local-l1.json` (addresses only, ignored too). The key and Council addresses the L1 genesis enables are the roster addresses, not the placeholders in `Backend/seed/may_labs.json`, so the script also writes `infra/l1/seed.l1-local.json` and the backend reads it through `GUARDIAN_SEED_FILE`.

Other targets: `make l1-policy-v2` (policy v2 through the Council), `make l1-local-checks` (T15 and T8 against the real precompiles; run `l1-policy-v2` first), `make l1-deploy|l1-seed|l1-handover` (single steps), `make verify-handover`. `NETWORK=fuji I_UNDERSTAND=fuji make deploy-contracts` targets Fuji and needs `RPC_URL`, `DEPLOYER_PK`, `SEED_FILE`, `TOP_UP_OPERATOR`, `L1_KEY_COUNCIL_TRANG|LAN|HUY` in the environment (see `infra/l1/contracts.sh`); it writes `Backend/deployments/fuji-l1.json` and has not been run (no funded Fuji key, no Fuji L1 yet).

Seeding goes through real Council proposals, so the vault's `policyVersion` is not 1 on a real deployment: it is 4 after the bootstrap (1 + two seed proposals + the top-up operator proposal) and one more after policy v2. The sim and the anvil tests still start at 1.

The anvil suites (`uv run pytest tests/chain_l1 tests/conformance`, need Foundry; they skip without it) keep running in CI. Startup errors name the missing variable or file; `DEMO_MODE` is refused on a chain id outside `DEMO_CHAIN_IDS` (default anvil 31337 and local L1 424242). `POST /api/demo/reset` answers 409 on L1. Details: `docs/modules/chain-adapter/README.md`.

## Test / lint / build
    make test
    make lint
    make build

Pre-push runs backend pytest; pre-commit runs ruff, eslint, tsc, gitleaks and file hygiene hooks.

## Docker
    make docker-up      # api :8000, web :8080 (live mode, /api proxied)
    make docker-down

## GitHub Pages
`.github/workflows/pages.yml` builds with `VITE_API_MODE=mock VITE_BASE=/Cordon/`, copies `index.html` to `404.html` (SPA deep links) and deploys.
Repository setting: Settings > Pages > Source = "GitHub Actions".

## Blender
`make blender-rebuild` runs `Blender/scripts/rebuild.sh`. Sources live in `Blender/out/*.blend`. Scripts currently assume the repo is at `~/Documents/Cordon`.

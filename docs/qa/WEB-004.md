## Why scene 4 was blocked (real-chain differences)

1. **The `agent` container runs a swap every 5 minutes** (`agent-1`: "cycle outcome=swapped amount=5.000" at 03:00, 03:05,
   03:10, 03:16 UTC). Four swaps used all of `key_agent_rebalance`'s 20.000 daily cap, so scene 4 step 0 could not swap
   (`409 AGENT_STEP0_FAILED`) and the next cycles were `CARD_DAILY_CAP`.
2. **The incident manager then locked the district on its own**: "incident 1 opened: Khu Anh Minh liên tục chi vượt hạn mức (B04)"
   at 03:26, `lockPrincipal(minh)` block 897 and incident proposal #15 (block 898). The demo state was unusable (scene 5
   shows "đã khoá") until a reset. (Not checked why the earlier e2e runs did not hit it; probably they ran right after a reset, within minutes.)
3. **Stale attempts hijack scene 4.** `/api/attempts` returned 43 rows from earlier simulated runs (`simulated: true`,
   `DISTRICT_LOCKED`, `principalSpentAfter` 25.000). They survive a container restart (kept at startup by design,
   `demo_reset.py`), and the stage derives "Đã dùng chung" from the newest attempt, so the bar showed 25.000 before any
   step and steps 1-2 were already ticked, step 2 disabled (`attackDone`). A non-startup reset clears them (0 after reset).
4. After the reset the browser kept the old 44 attempts and "Xem lại bản đã lưu 44/44" (cached client state; the `reset`
   SSE event does not clear it).
5. **API slowness**: every endpoint (`/api/health`, `/api/graph`, `/api/proposals`) took 5-26 s, the API container at
   40-60 % CPU while idle, host load average 8-23 (Docker VM, two Chrome renderers with the WebGL city, XProtect). The UI showed
   a proposal 25 s late; the page needed more than 30 s to render `/chi-tiet/map`. First minutes after the stack came up were fast.
6. `BLOCK_STALLED` warning in `/api/health` whenever no tx is sent (the L1 only produces blocks for txs); `SSE_SLOW` warning always.
7. `Frontend/.env.example` named `VITE_L1_EXPLORER_URL` but the code reads `VITE_EXPLORER_URL` (fixed).
8. `demo-reset.sh` probes the API with a 5 s timeout; the loaded API missed it, so step 6 was skipped ("restart it") and
   `POST /api/demo/reset` had to be called by hand (29 s, seeded #12; #13 also open).

## Latency (not 10 samples)

Method: a second `EventSource('/api/stream')` in the page, timestamped on arrival, compared with the block timestamp of the
tx (`cast block`), plus the backend `eventToSse` counter in `/api/health` (event receipt to SSE publish).

| Sample | Result |
|---|---|
| Approve Lan, block 899 (ts 1794886104) -> browser SSE `proposal_updated` at 1794886109.6 | 5.6 s (the HTTP call took 9 s) |
| Approve Trang, block 900 (ts ...128) -> browser SSE at ...134.4 | 6.4 s (HTTP call 15 s) |
| Keeper execute, block 902 (ts ...151) -> browser SSE `city_updated` at ...149.5 | block ts is ahead of the wall clock, not usable; backend `eventToSse` 2.2 s |
| Backend `eventToSse` readings in `/api/health` | 6.58 s, 9.67 s, 2.16 s, then 1.72 s (last of 100 samples after the reset, max 6.63 s) |

Screen time (DOM) was not measured: the page rendered 10-30 s late. No 10 consecutive events were produced (scene 4 blocked),
so (d) is open. Re-run on an idle host with the agent container stopped.
